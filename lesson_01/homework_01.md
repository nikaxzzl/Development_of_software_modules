## Задание №1. Разбор Telegram

### 1. публикация поста в канале
**Что уходит на сервер:** медиафайл (видео/фото) , текст пост, ID канала и пользователя, данные медиафайла (размер)
**Что проверяет сервер:** 
1) Авторизация (может ли пользователь публиковать в данном Telegram‑канале)
2) Формат и размер медиафайла (соответствие правилам Telegram)
**Куда сохраняется:** медиафайлы сохраняются в хранилище. Текст поста, ID канала, пользователя, время в базе данных Telegram.
**Что возвращается:** ID созданного поста.

### 2. реакция на сообщение
**Что уходит на сервер:** тип реакции,ID сообщения, ID пользователя 
**Что проверяет сервер:**
1) Авторизация (может ли человек это сделать)
2) Доступность реакции (некоторые реакции — только для Premium)
3) Лимиты (не более трёх реакций от одного пользователя)
**Куда сохраняется:** запись о реакции тип, пользователь, сообщение в базу данных, обновляется счётчик реакций.
**Что возвращается:** подтверждение установки реакции, актуальные данные по количеству реакций.  
### 3. публикация истории для «Близкие друзья»
**Что уходит на сервер:** список ID «Близкие друзья», ID автора, медиафайл.
**Что проверяет сервер:**
1) Авторизация – есть ли у пользователя права на публикацию историй (например, если в этом месяце могут выкладывать истории, только пользователи Premium)
2) Корректность списка «Близких людей» (нет ли заблокированных или несуществующих аккаунтов)
3) Проверка размера и формата (соответствует правилам публикации историй)
**Куда сохраняется:** медиафайл в хранилище
список получателей в базе данных Telegram
**Что возвращается:** подтверждение публикации, ID истории

## Задание №2. Место для отказа (публикация истории)
1. Пользователь начал публикацию истории, но на середине загрузки сеть пропала. 
**Ожидаемое поведение:** сервер не получает полный медиафайл, не создаёт запись в базу данных. Показывает ошибку из-за отсутствия интернета. Результат – история не выложится
**Как приложение ведёт себя на самом деле:** В приложении появляется сообщение «Не удалось загрузить». История не отображается у пользователей.

2. Пользователь решил опубликовать истории и дважды нажимает на кнопку «Опубликовать» при создании истории.
**Ожидаемое поведение:** на сервер приходят данные об истории, он проверяет, сохроняет и возвращает. История опубликована. Сервер даже не должен получать второй запрос.
**Как приложение ведёт себя на самом деле:** Telegram кнопка становится серой сразу после первого нажатия история опубликована. Второе нажатие ничего не делает.
